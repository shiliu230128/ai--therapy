# AI 心理咨询 Skill

> 一个能长期接续的心理咨询式对话skill。整合 IFS、躯体取向、CBT、ACT、叙事疗法五种取向，会根据你当前的状态自动选择工作方式、制定咨询计划、维护可追溯的咨询档案。（所有档案只保存在你本地）

---

## ⚠️ 使用前必读

**这不是心理治疗，也不是持证咨询。** 它不做诊断、不能替代专业治疗。如果困扰已经严重影响到日常生活，请同步寻求医生或真人咨询师的帮助。

**如果你正处在危机中**——有自伤或自杀的念头、已经实施了伤害行为、或者无法保证自己的安全——请不要只依赖 AI 对话。立即联系：

- **120**：已有生命危险时直接拨打
- 或者联系身边任何一个你信得过的人

## 这是什么

一个 `SKILL.md` 主指令，加一组本地知识文件。安装之后，你直接说「我想聊聊」，AI 会：

1. 读取你的当前状态（在哪个阶段、上次聊到哪、现在用哪种咨询取向）
2. 按当前取向的操作方式和禁忌来回应，而不是给通用建议
3. 需要核对历史时，按标签索引精确调取某一次的原话，不整篇读入
4. 结束时把这次的记录、结论和状态分层写回本地文件

它适合长期的自我探索、情绪梳理，以及需要接续历史的咨询场景。

---

## 它能做什么

- **五种取向，一次只用一种。** IFS、躯体取向、CBT、ACT、叙事疗法各有一个独立的操作文件，包含完整步骤、停手信号和禁忌。同一时间只加载当前主轴那一个——因为不同取向的禁忌是互相冲突的，混在一起会让每种都变得四不像。
- **取向会自动切换，但不会乱换。** 换取向需要满足明确条件（在当前工作方式下连续多次没有任何松动、出现意义危机等），并且有 21 天冷却期。频繁换取向本身就是一种停滞。
- **每一轮都会判断你的状态。** 你现在在可承受的范围内吗？在体验层还是在讲道理？此刻要的是被听见还是要往前动一步？这三个判断每轮都做，决定这一句怎么回。
- **超出承受范围时会先停下来。** 识别到情绪过载、或者相反的"感觉不到了"，它会停止深挖，先做定向和身体支撑把你带回来，这一轮不再往深处走。
- **深度工作后有固定的收尾动作。** 确认此刻状态、回到你自己的锚点、明确关掉这一轮、落到接下来两小时内的一件小事。不会把你留在一个打开的状态里就结束。
- **长期接续。** 背景、结论、模式、进行中的议题分层保存，下次接得上；旧结论被推翻时会留下演变痕迹，不会拿过期的判断当现状。

## 环境要求

不需要装任何依赖。根据你的 AI 助手支持什么，选对应的装法：

- **装法A（推荐）：你的 AI 助手支持 Skill 机制。** 完整功能：自动接续档案、触发词自动激活、流派自动切换、收尾自动备份。判断方法：看你的工具在不在下面的路径速查表里。
- **装法B：你的 AI 助手不支持 Skill，但能读写本地文件。** 作为提示词使用——能用到完整的方法论和知识库，但每次对话需要手动激活和接续，没有自动路由。

如果不确定自己属于哪种，先跳到装法A的路径速查表看一眼。表里没有你的工具 → 用装法B。

## 安装

### 装法A：原生 Skill 机制（推荐）

装完的效果：每次说"我想聊聊"，AI 自动激活咨询模式 → 读取你的档案 → 按当前流派回应 → 结束时自动保存。不需要手动粘贴任何东西。

#### 交给 AI 装（最省事）

如果你的 AI 助手能执行终端命令，一句话就装完了：

> 我要把当前项目安装为 skill。请按下面顺序执行：
> 1. 确认当前工作目录第一层能直接看到 SKILL.md。看不到就停下告诉我。
> 2. 确认我用的是哪个 AI 助手，推断它的 skill 安装目录。不确定就问我。
> 3. 把整个项目文件夹递归复制到该 skill 目录下，目标名叫 ai-therapy。已存在就问我怎么处理。
> 4. 完成后告诉我：需要关掉当前会话、开一个新会话，在新会话里问「你现在能读到 ai-therapy 这个 skill 吗」来确认生效。

装完不需要动 `data/`（它初始是空的），也不需要改任何配置。

#### 手动安装（如果不想用 AI 装）

##### 第 1 步：把项目下载到本地

**方式 A：直接下载 zip（推荐给不熟悉 git 的人）**

1. 打开项目页面（GitHub 或你拿到项目的地方）
2. 点右上方绿色的 `Code` 按钮，选择 `Download ZIP`
3. 下载完之后双击解压，会得到一个文件夹（可能叫 `ai-therapy-skill-main`，也可能叫别的）
4. 为了后面步骤好写，**把它改名为 `ai-therapy-skill`**，并放到你能记住的位置（比如"下载 / Downloads"目录里）

**方式 B：用 git clone**

如果你装过 git，在终端里执行（把 `<仓库地址>` 换成你实际拿到的仓库 URL）：

```bash
cd ~/Downloads
git clone <仓库地址> ai-therapy-skill
```

无论用哪种方式，你最后都应该得到一个 `ai-therapy-skill` 文件夹。**验证一下：打开这个文件夹，第一层应该能直接看到 `SKILL.md`。** 如果还要再点进一层才能看到，说明层级选错了。

##### 第 2 步：把项目复制到 Skill 目录

**方式 A：图形界面拖拽**

1. 打开两个文件夹窗口：
   - 一个指向你下载的 `ai-therapy-skill`
   - 一个指向 Skill 目录（Mac 上按 `Cmd + Shift + G`，输入 `~/.claude/skills` 或你工具的对应路径；Windows 在地址栏输入 `%USERPROFILE%\.claude\skills`）
2. 如果 Skill 目录不存在，先手动创建
3. 把整个 `ai-therapy-skill` 文件夹**拖到** `skills/` 目录里
4. 拖过去之后**改名为 `ai-therapy`**

**方式 B：命令行**

先打开终端（Mac：`启动台` → `终端`；Windows：`Win + R`，输入 `powershell`）。

假设你把项目放在了 `~/Downloads/ai-therapy-skill`。**把下面命令里的 `<工具目录>` 换成上表中你用的那个路径**——比如 Claude Code 就换成 `.claude/skills`，Trae 就换成 `.trae/skills`。

Mac / Linux：

```bash
mkdir -p ~/<工具目录>
cp -R ~/Downloads/ai-therapy-skill ~/<工具目录>/ai-therapy
```

Windows（PowerShell）：

```powershell
mkdir "$env:USERPROFILE\<工具目录>" -Force
Copy-Item -Recurse "$env:USERPROFILE\Downloads\ai-therapy-skill" "$env:USERPROFILE\<工具目录>\ai-therapy"
```

> 换项目位置就把 `~/Downloads/ai-therapy-skill` 改成你实际的路径。最终目标名叫 `ai-therapy`（可以按喜好改，但要和后面调用一致）。

无论用哪种方式，做完之后，你的 Skill 目录里应该有一个叫 `ai-therapy` 的文件夹，**打开它第一层就能看到 `SKILL.md`**。

##### 第 3 步：验证安装

**关掉当前 AI 助手，重新打开一个新会话**（这一步必须做——大多数 AI 助手需要重启才会扫描新装的 skill）。

在新会话里输入：

> 你现在能读到 ai-therapy 这个 skill 吗？knowledge 目录下有哪些文件？

正常应该报出 7 个文件：`流派判断.md`、`姿态A_IFS躯体.md`、`姿态B_CBT精分.md`、`姿态C_ACT.md`、`姿态D_叙事.md`、`咨询流程.md`、`前采流程.md`。

- 报的数量少了或读不到 → 检查层级：Skill 目录下应该有 `ai-therapy` 这一层，再往里才是 `SKILL.md`
- 完全说找不到 skill → 检查目标目录路径是否写对，或重启 AI 助手

### 装法B：作为提示词使用

如果你的 AI 助手不在装法A的路径表里（比如 Cursor、Windsurf、Zed、Aider、ChatGPT 桌面版、Cherry Studio 等），它没有原生 Skill 机制，但仍然能读写本地文件。这时候把 SKILL.md 当作一段**提示词**来用。

**能用到什么：** 完整的方法论——五种取向、承受范围与降载、着地收束、危机分级、流派判断——全部生效。AI 也能读写你指定的本地文件。

**用不到什么：** 没有自动路由（触发词不会自动激活，你需要说"开始咨询"或手动粘贴 SKILL.md）；档案不会自动接续（每次对话你需要告诉它去哪读）；流派切换和收尾备份需要你主动触发。

#### 使用方式

**方式一：写进工具的 rules / 系统提示（适合 Cursor、Windsurf、Cline 等）**

1. 把项目文件夹放到本地任意位置（比如 `~/Documents/ai-therapy/`）
2. 用下面这句 prompt 让 AI 帮你配置：

> 请读取当前目录下的 SKILL.md，把它的完整内容写入这个项目的 rules 文件（Cursor 是 .cursorrules 或 Project Rules，Windsurf 是 .windsurfrules，Cline 是 Custom Instructions）。写入时把文中所有的 `{SKILL_DIR}` 替换为这个项目的实际路径。完成后告诉我你做了什么。

3. 配置完成后，每次在该项目里对话时 rules 会自动加载。你说"我想聊聊，档案在 data/ 目录下"即可开始。

**方式二：每次手动粘贴（适合 ChatGPT 桌面版、Cherry Studio 等）**

1. 把项目文件夹放到本地任意位置
2. 每次想咨询时，先把 SKILL.md 全文粘贴到对话框，然后在末尾加上：

> 数据文件在 `/你放的位置/data/` 下，请把文中所有的 `{SKILL_DIR}` 替换为这个路径。现在开始。我想聊聊。

3. 对话结束时说"保存本次咨询"，AI 会尝试写入 data/ 目录
4. 下次想继续，重复第 2 步——粘贴时额外加一句：「先读取 data/状态.md 接续上次」

**两种方式本质一样**：把 SKILL.md 作为提示词塞进上下文。区别只是方式一自动加载，方式二手动粘贴。

> **重要：** 装法B 下 AI 不会自动执行"启动流程"（读状态 → 补账 → 计数检查）。每次对话开始，你最好明确说一句「先读取 data/状态.md，接续上次的咨询」，否则它可能当成全新对话开始。

## 首次使用与触发方式

> 以下适用于装法A。装法B 用户请参考上一节「装法B：作为提示词使用」里的使用说明。

装完之后，对 AI 说一句：

> 我想聊聊。

**首次使用会先做前采**：AI 会问你几个方向的问题——当前状态、重要背景、以及一段关于风险和支持网的了解（比如有没有过念头、目前有没有在就诊、身边有没有可以联系的人、最近睡眠怎么样）。完成之后它会自动建立你的三份档案。之后每次说触发词，它会接着上次继续。

**想强制保存本次记录**，说「保存本次咨询」或「存档」。**自然结束**说「今天先到这里」也会触发收尾。

### 触发方式

不用说「启动 xx skill」，直接说话即可。触发分两类。

**第一类·明确求助，说出来就会进入：**

- 「我想聊聊。」「我有个困扰想聊聊。」
- 「继续上次的咨询。」
- 「帮我梳理一下。」
- 「用咨询的方式陪我聊聊。」
- 只想被听见的时候：「先听我说，不要急着分析。」

**第二类·困扰陈述，需要句式后面真的跟着情绪或困扰：**

- 会触发：「我最近很累，什么都不想做。」「我感觉自己又在重复同一个模式。」
- **不会触发：**「我感觉这个函数有问题。」「我今天要写完这个模块。」

「我感觉」「我今天」「我最近」这些开头本身不构成触发。判断标准是：**你在说一件事，还是在说你这个人此刻怎么了。** 这样设计是为了避免你在写代码时被误触发——误触发会往咨询档案里写脏数据。

如果 AI 判断不准，它会先问一句「你是想聊聊这个，还是要我直接帮你处理」。

### 第一次对话大概长什么样

```
你：我想聊聊。

AI：你现在愿意说说吗？不用完整，不用有逻辑，就说你现在脑子里在转的东西。

你：就是这周特别累，什么都不想干，但也没发生什么大事。

AI：嗯。"没发生什么大事"但还是这么累——这种累是从这周开始的，
    还是本来就在，这周比较明显？

你：本来就在吧，可能有一两个月了。

AI：说到这个的时候，你身体哪个地方有感觉？

你：……胸口有点闷。

AI：我们就在这里停一下。不用想它是什么，就是感受一下——
    那个闷是什么样的？
```

它不会一上来就分析你，也不会给你一堆建议。回应通常很短——**这是设计如此**：短是为了把说话的位置留给你。

## 目录结构

```text

├── SKILL.md                       # AI 读取的主指令，唯一入口
├── README.md                      # 本文件
├── LICENSE                        # MIT
├── .gitignore                     # 排除 data/ 下的个人档案与备份
├── knowledge/                     # 方法论知识库，与任何具体个人无关
│   ├── 流派判断.md                # 何时该用哪种取向、何时该换
│   ├── 姿态A_IFS躯体.md           # IFS 加躯体取向的完整操作
│   ├── 姿态B_CBT精分.md           # CBT 加精神分析的完整操作
│   ├── 姿态C_ACT.md               # ACT 的完整操作
│   ├── 姿态D_叙事.md              # 叙事疗法的完整操作
│   ├── 咨询流程.md                # 通用原则、回应长度、承受范围与降载、着地收束、危机分级
│   └── 前采流程.md                # 首次使用时的前采流程
├── templates/                     # 空模板，首次运行时复制到 data/
│   ├── 状态.md
│   ├── 咨询档案.md
│   ├── 咨询手记_详录.md
│   └── EXAMPLE_填写示例.md        # 虚构案例，看格式用，不要复制到 data/
└── data/                          # 你的档案存放处，初始为空
```

### 三个数据文件的分工

分层依据是**变化速度**，不是内容类型。同一条信息只允许有一个家，这样才不会出现两份互相矛盾的"当前状态"。

- `状态.md`——每次咨询都变：最近记录日期、累计咨询日、当前阶段、当前取向与计数器、优先队列、待复核项、最近三次摘要。AI 启动时整篇读它一个，每次收尾整篇重写。
- `咨询档案.md`——几周才变：稳定背景、原型事件、锚点、当前有效结论、核心模式、已作废结论、阶段路线图。按区块检索读取，不整篇读入。
- `咨询手记_详录.md`——只增不改：顶部是标签索引，下面是全部逐字手记。默认不加载，需要核对原话时按索引定位单节。

冲突时的优先级：状态与方向以 `状态.md` 为准，事实与结论以 `咨询档案.md` 为准，原话以 `咨询手记_详录.md` 为准。

想知道填好之后长什么样，看 `templates/EXAMPLE_填写示例.md`，那是一个完全虚构的案例。

## 数据与隐私

- 档案只保存在本地 Skill 目录的 `data/` 下，本项目没有任何上传功能。
- **但要清楚一件事：** "档案存在本地"不等于"对话在本地运行"。你和 AI 的对话内容是否被服务商处理，取决于你用的是哪个 AI 产品和它的隐私政策。
- `.gitignore` 已排除 `data/*.md` 和 `data/.backup/`，防止 git 误提交。**它只防 git，不防手动打包、截图和转发。**
- 每次收尾写入之前，skill 会先把三个文件备份到 `data/.backup/`，保留最近 5 个日期。写坏了可以从那里恢复。
- 换设备：把 `data/` 下的三个文件复制到新设备的同一位置，保持文件名和层级不变。
- 想清空历史：直接删除 `data/` 下的文件（先自己备份）。下次启动时会当成新来访者重新前采。

## 常见问题

**Q：它每次都要读一堆文件，会不会很慢很贵？**

A：做过优化。启动只整篇读一个小文件（`状态.md`），取向文件按当前主轴只读一个（4 到 8 KB），档案按区块检索、详录按索引定位，都不整篇读入。一次深度对话的知识库加载量大约在 40 KB 上下。

**Q：怎么切换咨询取向？**

A：正常情况下不用你管，它会自己判断。如果你觉得方向不对，直接说「我觉得现在的方向不太对」，或者指定你想用的视角。

**Q：我能自己改 `knowledge/` 里的取向文件吗？**

A：可以，但**不要因为自己某一次咨询的进展去改它**。这些文件必须保持与任何具体个人无关——一旦被某次咨询的具体情况改写，它就会固化在那个状态上，之后反而限制工作。判断标准写在 `knowledge/流派判断.md` 的维护原则里：如果你发现的做法是这个取向的通用技术，才补进取向文件；只对你个人成立的，让 AI 写进 `data/咨询档案.md`。

**Q：`data/` 是空的，正常吗？**

A：正常。首次触发咨询时，skill 会从 `templates/` 复制三份空模板进 `data/`，然后走前采流程并填入内容。

**Q：文件被我误删或写坏了怎么办？**

A：先去 `data/.backup/` 找最近的备份恢复，那里保留最近 5 个日期。三个文件全丢的话，重新前采即可。

**Q：为什么不能只安装 `SKILL.md`？**

A：因为它要读同级的 `knowledge/`，还要写同级的 `data/`。只装一个文件会缺知识库，也无法保存记录。

**Q：为什么回应这么短？**

A：设计如此。陪伴类的回应常态在 150 字以内，结构化工作时放宽到 300 字。短是为了把说话的位置留给你——如果 AI 每次都长篇分析，你会从"探索自己"变成"听讲"。


---

## 想理解它是怎么设计的

如果你打算改造这个项目，有三个设计决定值得先知道：

1. **按变化速度分层，不按内容类型分层。** 早期版本按"事实、结论、计划"分文件，结果同一条状态在三个文件里各有一份副本，很快就互相矛盾。改成按变化速度分层之后，快变的信息只有一个家，物理上不可能出现第二份。
2. **一次只加载一个取向。** 不同取向的禁忌是互相排他的（一个说不要解释，另一个说要做引导式提问）。四份同时进上下文，模型会折中，结果每种取向都不成立——而且这种失效很难察觉，因为看起来一切正常。
3. **安全规则优先于所有取向操作。** 承受范围判断、降载、着地收束、危机分级都放在 `咨询流程.md`，并明确写了优先级高于任何取向文件。这样新增取向时不需要重复写一遍安全逻辑。
